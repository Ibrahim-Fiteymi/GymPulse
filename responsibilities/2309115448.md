### Delivered Tasks

#### 1. Authentication System (`auth.py`)

Implemented the full JWT-based authentication system:
- **Token creation** using PyJWT with HS256 signing, 8-hour expiry, and a payload containing `sub` (graph node ID), `role`, `name`, and `exp`
- **Password hashing** using bcrypt with `gensalt()` — a new salt is generated for every password, preventing rainbow table attacks
- **Two FastAPI dependency functions**: `require_admin` (403 if role ≠ admin) and `require_member_or_admin` (401 if no valid token) — composable and reused across all protected routes
- **`auto_error=False`** on the HTTPBearer scheme — lets the dependency function return a clean 401 with a readable message instead of FastAPI's generic 403 "Not authenticated"

#### 2. Security Hardening

**Backend:**
- Member identity is **injected from the JWT**, not read from the request body — a member cannot spoof another member's identity by passing a different `member_id` in the JSON
- Reservation ownership check at update time — member's JWT `sub` must match the reservation's stored `member_id`
- Cancellation of already-started reservations is rejected server-side (not just client-side)
- Equipment under maintenance cannot be reserved — checked in the service layer against the stored status before the overlap query

**Frontend:**
- 401 responses automatically clear the stale token from `localStorage` — no manual logout needed after expiry
- Demo credentials removed from all UI (Login page, Checkout test card hints) and stored only in `credentials.md`
- PayPal modal shows no pre-filled sandbox credentials

#### 3. Security Hardening (Additional Measures)

**Rate limiting on login endpoints:**

Both `/auth/admin/login` and `/auth/member/login` are protected with `slowapi` to prevent brute-force password attacks:

```python
limiter = Limiter(key_func=get_remote_address)
app.state.limiter = limiter

@app.post("/auth/admin/login", response_model=Token, tags=["Auth"])
@limiter.limit("10/minute")
def admin_login(request: Request, data: LoginRequest, graph: Graph = Depends(get_graph)):
    ...
```

A custom 429 exception handler returns JSON (not plain text) so the browser can read the error through CORS:

```python
@app.exception_handler(RateLimitExceeded)
async def rate_limit_handler(request: Request, exc: RateLimitExceeded) -> JSONResponse:
    return JSONResponse(status_code=429,
        content={"detail": "Too many login attempts. Please wait a moment and try again."})
```

The frontend `api.js` surfaces 429 errors with a readable message:

```javascript
if (res.status === 429) {
    throw new Error(body?.detail || "Too many attempts. Please wait and try again.");
}
```

**Parameterized Cypher query in seed data:**

The `_seed_data_if_empty()` function previously used f-string interpolation to build Cypher queries with database IDs. Although these IDs came from the database itself (not user input), it was bad practice. Converted to fully parameterized queries:

```python
graph.query(
    """MATCH (e:Equipment), (m:Member)
    WHERE ID(e) = $eq_id AND ID(m) = $mem_id
    CREATE (u:UsageLog { ... })""",
    {"eq_id": eq_id, "mem_id": mem_id, ...}
)
```

**Default secret key warning:**

Added a startup check that prints a clearly visible warning if the JWT `SECRET_KEY` is still set to the development default, reminding operators to set the environment variable before deployment.

### Key Technical Decisions

- **`credentials.md` instead of hardcoded UI hints** — keeps the UI clean and realistic while ensuring demo credentials are accessible to presenters
- **Two-layer overlap detection** (edge traversal + property fallback) — ensures conflict detection works regardless of whether the reservation was created by the API (with BOOKED_BY edge) or by the seed script (property-only)
- **`background_tasks.add_task`** for WebSocket broadcast — the HTTP response returns immediately; the broadcast happens asynchronously, keeping API response times low under concurrent load
