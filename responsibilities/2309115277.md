#### 4. Security Additions

**`_warn_default_secret()` startup check:**

Added a startup function that detects when the JWT signing key is still set to the hardcoded development default and prints a prominent warning to the console:

```python
def _warn_default_secret():
    default = "gympulse-dev-secret-change-in-production"
    if os.getenv("SECRET_KEY", default) == default:
        print("=" * 60)
        print("WARNING: JWT SECRET_KEY is set to the default dev value.")
        print("Set the SECRET_KEY environment variable before deploying.")
        print("=" * 60)
```

This runs first in `on_startup()` before any database operations, ensuring the warning is never missed during development or staging.

**Parameterized seed queries:**

Converted f-string Cypher interpolation in `_seed_data_if_empty()` to fully parameterized queries. Even though the interpolated values came from the database (not user input), parameterized queries are the correct pattern and eliminate any future risk if the code is modified:

```python
graph.query(
    """MATCH (e:Equipment), (m:Member)
    WHERE ID(e) = $eq_id AND ID(m) = $mem_id
    CREATE (u:UsageLog { start_time: $start, end_time: $end,
        duration_minutes: $duration, queue_wait_minutes: $wait_time,
        member_name: $mem_name })
    CREATE (u)-[:USED]->(e) CREATE (u)-[:LOGGED_BY]->(m)""",
    {"eq_id": eq_id, "mem_id": mem_id, "start": start.isoformat(),
     "end": end.isoformat(), "duration": duration,
     "wait_time": wait_time, "mem_name": mem_name}
)
```

#### 5. Global Error Handling

Implemented the catch-all `exception_handler` for unhandled 500 errors. Returning JSON (rather than a plain HTTP 500) ensures CORS headers are still sent, allowing the browser to read the error detail instead of receiving a CORS failure with no body.

#### 5. Equipment Name Migration

Designed `_migrate_equipment_names()` — a startup Cypher migration that renames legacy equipment nodes and updates any linked reservation nodes. This allowed renaming "Treadmill #1" → "Treadmill" and "Treadmill #2" → "Elliptical" on a live database without manual intervention.

### Key Technical Decisions

- **`DETACH DELETE`** for equipment deletion removes all edges, preventing orphaned nodes from polluting analytics counts
- **Dual overlap detection** (graph edge + node property fallback) ensures no reservation can be double-booked regardless of how the node was created (API vs. seed script)
- **`_auto_complete_past()` called from `summary()`** ensures the "active reservations" KPI is never inflated by stale confirmed statuses
