Delivered Tasks
1. Graph Schema Design
Designed the 10-entity graph schema and all relationship types. The key decision was choosing a graph database over a relational one: the core query patterns of GymPulse ("is this machine reserved right now?", "does this member have a conflicting booking?") map directly to graph traversal and would require multiple JOINs in SQL.

Defined all edge types and their semantic meaning:

RESERVES — links a Reservation to the Equipment it books

BOOKED_BY — links a Reservation to the Member who created it (enables ownership verification without querying a separate table)

ENROLLED_IN — M:N relationship between Member and WorkoutClass

LEADS — Trainer to WorkoutClass

USED — UsageLog to Equipment

LOGGED_BY — UsageLog to Member

LOCATED_IN — Equipment to GymZone

REPAIRS — MaintenanceTicket to Equipment

HAS_PLAN — Member to MembershipPlan

2. Pydantic Schema Layer (schemas.py)
Wrote all Pydantic v2 models for input validation and response serialization. Key implementations:

@model_validator(mode="after") on ReservationCreate — enforces end_time > start_time and the 60-minute duration cap at the schema level, before any business logic runs

no_blank_required_fields validator on EquipmentCreate — rejects whitespace-only strings that pass the min_length=1 check

Optional[datetime] on fields like join_date, hire_date, reported_date — prevents 500 errors when seeded nodes lack these fields

EmailStr type for member email — leverages email-validator for RFC-compliant validation

Regex patterns on status fields — only valid enum values accepted

3. Seed Data Strategy (_seed_data_if_empty)
Built the full seed system in a single atomic Cypher CREATE block that creates all node types, all zone relationships, and all member-plan relationships in one transaction. Followed by Python loops that create 56 UsageLog entries spread over 7 days and 1 seeded Reservation for Alice tomorrow.

4. Peak Hour Seed Data (_seed_peak_hour_reservations)
Designed the historical reservation seeding strategy for the analytics charts:

Distributes 53 reservations across 5 hour slots (7 AM×10, 8 AM×10, 9 AM×15, 1 PM×13, 2 PM×5)

Spreads records across 28 past days so no two reservations on the same equipment at the same hour on the same day conflict

Uses a guard (existing >= 50) to skip on populated databases

Key Technical Decisions
Using graph edges (not node properties) as the authoritative storage for relationships — this is why the service layer traverses RESERVES and BOOKED_BY edges rather than reading equipment_id / member_id properties stored on the reservation node.

Optional datetime fields on read schemas prevent Pydantic ResponseValidationError (HTTP 500) for seeded nodes that were created without those fields.

The _align_log_times_to_5min() migration ensures all historical log end-times match the 5-minute picker interval, keeping displayed data visually consistent.

Dynamic CORS & Environment Routing: Decoupled the frontend from local hosts by using build-time environment variables, allowing the application to scale and be accessed globally without hardcoded URLs.
