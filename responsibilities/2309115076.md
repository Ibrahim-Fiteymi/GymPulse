## Role: Frontend Development & UI/UX Engineering

---

### Overview

I was responsible for the complete React frontend — component architecture, routing system, all page layouts, the design system, animations, and integration with the backend API.

---

### Delivered Tasks

#### 1. Application Shell & Routing (`App.jsx`)

Designed the hash-based routing system without React Router. The key engineering decision was using `history.pushState` instead of `window.location.hash =` assignment, which avoids firing the `hashchange` event twice and caused a double-navigation bug (requiring two clicks to navigate from non-dashboard pages).

Built the full auth state management: JWT token stored/retrieved from localStorage, role-based tab visibility (Admin tab only for admins), automatic redirect after login based on role.

#### 2. Dashboard (`Dashboard.jsx`)

The most complex component. Implements:
- 15-second polling loop with cancellation on unmount (using a `cancelled` flag to prevent state updates on unmounted components)
- Animated number counters (`AnimatedNumber`) using `requestAnimationFrame` with cubic ease-out — no external library
- Scroll-triggered section reveals using `useInView` from Framer Motion
- Equipment cards with conditional background images, object-position tuning per machine, and 3D perspective hover effect via `Card3D`
- Date-picker-driven peak hours chart — fetches new data whenever the selected date changes

#### 3. Reservations (`Reservations.jsx`)

Built the full reservation management UI with `react-datepicker` configured for 5-minute intervals. The form validates on the client before hitting the API: future-only start time, end > start, 60-minute max, and a real-time check against the member's existing confirmed reservations. Error messages appear inline per field, not as a generic alert. Status filter dropdown triggers a fresh API call so the table always reflects the selected filter.

Members only see **future** reservations in the list — past reservations are filtered out client-side so members are not shown irrelevant historical data. Admins retain full visibility of all reservations regardless of date.

#### 4. Admin Panel (`Admin.jsx`)

Equipment CRUD form with field-level validation and inline error display. Edit mode pre-populates the form and scrolls to top. Delete triggers a confirmation dialog before the API call. The status dropdown only exposes "Available" and "Maintenance" — the two statuses with real effect — avoiding the misleading "In Use" / "Reserved" options that the live status computation would override anyway.

#### 5. Checkout (`Checkout.jsx`)

Three-phase payment simulation: Visa/MasterCard card form with live formatting (`4111 1111 1111 1111`), fake PayPal modal with realistic white-box UI, 2.4-second processing animation with spinner, and success/failure result screens with full transaction details. Transactions saved to `localStorage`. Handles direct URL navigation to `#checkout` by redirecting to membership if no plan is selected.

#### 6. Static Pages

Built `AboutUs.jsx`, `Membership.jsx`, `ContactUs.jsx`, `Login.jsx`, `Footer.jsx`, `CinematicIntro.jsx`, and `Card3D.jsx` with consistent Framer Motion animation patterns (fade-up on mount, stagger delays per card).

#### 7. Design System (`App.css`)

Wrote the full 2,300+ line CSS design system including:
- CSS custom properties for the full color palette, spacing, radius, and transition tokens
- Glassmorphism card pattern (`backdrop-filter: blur`, `rgba` backgrounds, inset border highlights)
- Equipment card background-image positioning per machine (`background-position: 68% 60%` for Treadmill, etc.)
- All checkout, membership, footer, about, contact, and admin page styles
- Responsive breakpoints for mobile/tablet

---

### Key Technical Decisions

- **`publicDir: '../pics'`** in `vite.config.js` — serves all images from the project-root `pics/` folder at root URL without copying them into the frontend directory
- **`display: none` for Dashboard** instead of conditional rendering — keeps the polling interval alive even when other pages are shown, so data is fresh the moment the user returns
- **`history.pushState` instead of hash assignment** — prevents the double-navigation bug
- **Per-field error state** in forms (not a single error string) — each field shows its own validation message without clearing others
